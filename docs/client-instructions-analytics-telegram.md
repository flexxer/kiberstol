# Инструкция для клиента: получение ID для аналитики и формы заявок

**Сайт:** Kiberstol.by
**Что нужно получить:** 2 ID для аналитики + 2 параметра для Telegram-бота
**Куда вставлять:** аналитика — в админку сайта (`/keystatic` → «Настройки сайта» → «Аналитика»); Telegram — передать разработчику/хостингу (это секретные данные, в админку их вводить нельзя).

## Итоговый чек-лист (что должно быть на руках)

| № | Что получить | Как выглядит | Куда попадает |
|---|---|---|---|
| 1 | Google Analytics 4 — Measurement ID | `G-XXXXXXXXXX` | Админка → Настройки сайта → Аналитика → «Google Analytics 4 ID» |
| 2 | Яндекс.Метрика — номер счётчика | `12345678` (только цифры) | Админка → Настройки сайта → Аналитика → «Яндекс.Метрика ID» |
| 3 | Telegram — токен бота | `1234567890:AAH...` (длинная строка) | Передать разработчику (сервер, переменная `TG_BOT_TOKEN`) |
| 4 | Telegram — ID чата | `123456789` или `-1001234567890` | Передать разработчику (сервер, переменная `TG_CHAT_ID`) |

> ⚠️ Пункты 3 и 4 — **секретные**. Не отправляйте их в открытых чатах, не публикуйте в документах и не вставляйте в админку сайта. Токен даёт полный контроль над ботом.

## 1. Google Analytics 4 (GA4)

### Шаг 1. Вход

1. Откройте [analytics.google.com](https://analytics.google.com).
2. Войдите под Google-аккаунтом, который будет «владельцем» аналитики (лучше — корпоративный, а не личный сотрудника).

### Шаг 2. Создание аккаунта и ресурса

1. Нажмите **«Администратор»** (шестерёнка внизу слева) → **«Создать»** → **«Аккаунт»**.
2. Название аккаунта: `Kiberstol`.
3. Нажмите **«Далее»** → создание ресурса:
   - **Название ресурса:** `Kiberstol.by`;
   - **Часовой пояс:** `Беларусь (GMT+3) — Минск`;
   - **Валюта:** `Белорусский рубль (BYN)`.
4. Нажмите **«Далее»** → **«Создать»**.

### Шаг 3. Поток данных (сайт)

1. Выберите платформу **«Веб»**.
2. **URL сайта:** `https://kiberstol.by`
3. **Название потока:** `Kiberstol.by — сайт`
4. Нажмите **«Создать поток»**.

### Шаг 4. Скопировать ID

На открывшейся странице потока найдите блок **«Идентификатор потока данных»** (Measurement ID) — он выглядит так:

```
G-XXXXXXXXXX
```

Скопируйте его целиком, начиная с `G-`.

> Если страница закрылась: **Администратор** → **«Потоки данных»** → выберите поток → ID указан в правом верхнем углу.

### Что НЕ подходит

- `UA-XXXXXX-X` — старый Universal Analytics, не используется.
- `GTM-XXXXXX` — это контейнер Google Tag Manager, для этого сайта не нужен.
- «Секретный ключ Measurement Protocol» — не нужен.

### Куда вставить

1. Зайдите в админку сайта: `https://kiberstol.by/keystatic`
2. Раздел **«Настройки сайта»** → блок **«Аналитика»**.
3. Поле **«Google Analytics 4 ID»** → вставьте `G-XXXXXXXXXX`.
4. Нажмите **«Сохранить»**.

## 2. Яндекс.Метрика

### Шаг 1. Вход

1. Откройте [metrika.yandex.ru](https://metrika.yandex.ru).
2. Войдите под Яндекс-аккаунтом (желательно корпоративным).

### Шаг 2. Создание счётчика

1. Нажмите **«Добавить счётчик»** (или «+» в списке счётчиков).
2. Заполните:
   - **Название:** `Kiberstol.by`;
   - **Адрес сайта:** `https://kiberstol.by` (можно `kiberstol.by`);
   - **Часовой пояс:** `(GMT+3) Минск`;
   - **Часовой пояс для отчётов** — тот же.
3. Включите галочки (важно — сайт уже настроен на эти функции):
   - ✅ **Вебвизор** (запись действий посетителей);
   - ✅ **Карта кликов**;
   - ✅ **Внешние ссылки, загрузка файла** (отслеживание переходов и скачиваний);
   - ✅ **Точный показатель отказов**.
4. Примите условия и нажмите **«Создать счётчик»**.

### Шаг 3. Скопировать номер счётчика

Номер счётчика — это **число из 8 цифр**, которое видно:

- в списке счётчиков рядом с названием;
- в коде установки: `ym(12345678, "init", ...)`.

Скопируйте **только цифры**, без `ym(`, кавычек и скобок.

### Куда вставить

1. Админка сайта → **«Настройки сайта»** → блок **«Аналитика»**.
2. Поле **«Яндекс.Метрика ID»** → вставьте `12345678`.
3. Нажмите **«Сохранить»**.

### Доступ для подрядчика (по желанию)

**Настройки счётчика** → **«Доступ»** → добавьте Яндекс-логин разработчика с правом **«Просмотр»**. Так он сможет проверить установку, не имея права менять настройки.

## 3. Telegram: токен бота и ID чата

Эти данные нужны, чтобы заявки с формы приходили в Telegram. Они хранятся **только на сервере** (переменные окружения `TG_BOT_TOKEN` и `TG_CHAT_ID`) и никогда не попадают в код сайта или админку.

### 3.1. Создание бота и получение токена

1. В Telegram откройте официального бота **@BotFather** (проверьте галочку верификации).
2. Отправьте команду `/newbot`.
3. Введите **имя бота** (отображается пользователям), например: `Kiberstol Заявки`.
4. Введите **username бота** — латиницей, обязательно заканчивается на `bot`, например: `kiberstol_orders_bot`.
5. BotFather пришлёт сообщение с токеном:

```
1234567890:AAH-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

6. **Скопируйте токен и сохраните в надёжном месте** (менеджер паролей).

> Если токен попал в чужие руки: в @BotFather → `/revoke` → выберите бота → получите новый токен и передайте его разработчику. Старый сразу перестанет работать.

### 3.2. Получение ID чата

Выберите один из вариантов — куда должны приходить заявки.

**Вариант A. Личный чат с ботом (самый простой)**

1. Откройте своего бота по ссылке `https://t.me/<username_бота>` и нажмите **«Запустить»** (или отправьте `/start`).
2. Откройте в браузере ссылку, подставив свой токен:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. В ответе найдите фрагмент `"chat":{"id":123456789,...}` — число и есть **ID чата** (положительное).

**Вариант B. Группа (несколько сотрудников видят заявки)**

1. Создайте группу, например «Заявки с сайта».
2. Добавьте бота в группу.
3. Сделайте бота **администратором** группы (иначе он не увидит сообщения).
4. Дополнительно: @BotFather → `/setprivacy` → выберите бота → **Disable** (чтобы бот видел все сообщения, а не только команды).
5. Напишите в группе любое сообщение (например, `/start@<username_бота>`).
6. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":-1001234567890,...}`.
7. ID группы **отрицательный** — копируйте вместе со знаком минус.

**Вариант C. Канал**

1. Добавьте бота в канал как **администратора**.
2. Опубликуйте любой пост.
3. В `getUpdates` найдите `"chat":{"id":-100...}` — ID отрицательный, копируйте со знаком минус.

> Если `getUpdates` вернул `{"ok":true,"result":[]}` — значит, сообщений ещё не было. Напишите боту/в группу и обновите страницу.

### 3.3. Передача данных разработчику

Передайте **двумя отдельными сообщениями** (или через менеджер паролей):

- `TG_BOT_TOKEN` = `1234567890:AAH...`
- `TG_CHAT_ID` = `123456789` (или `-1001234567890`)

Разработчик/хостинг прописывает их в окружении PHP на сервере. В репозиторий и в админку они не попадают.

### 3.4. Проверка

1. Откройте сайт, заполните форму заявки (имя + телефон), поставьте согласие на обработку данных.
2. Нажмите «Отправить».
3. В течение нескольких секунд заявка должна появиться в Telegram.

## 4. Как это работает на сайте

1. Клиент получает ID и вносит их в админке: **Настройки сайта → Аналитика**.
2. ID сохраняются в конфигурации сайта (`analytics.ga4Id`, `analytics.yandexMetrikaId`).
3. При открытии страницы ID передаются в разметку страницы.
4. Счётчики загружаются **только после согласия** посетителя на категорию «Аналитика» в cookie-баннере.
5. Токен и chat_id бота хранятся на сервере; форма отправляет заявку на сервер, а сервер — в Telegram.

Важно: по закону РБ № 99-З счётчики **не запускаются**, пока посетитель не дал согласие в cookie-баннере (кнопка «Принять всё» или галочка «Аналитика»). Это нормальное поведение, а не ошибка.

## 5. Проверка после ввода ID

| Что проверить | Как |
|---|---|
| GA4 работает | Откройте сайт в режиме инкогнито → «Принять всё» → в GA4 раздел **«Отчёты → В реальном времени»**: должен появиться 1 активный пользователь |
| Метрика работает | Аналогично: Метрика → **«Сводка»** или значок «Онлайн» — визит должен отобразиться |
| Заявка приходит | Отправить тестовую заявку с формы, проверить Telegram |
| Изменения применились | После «Сохранить» в админке изменения попадают в репозиторий; сайт обновится после публикации (сборки). Если ID не появился — уточните у разработчика, выполнена ли публикация |

**Сроки появления данных:** GA4 и Метрика показывают посещения в реальном времени сразу; полноценные отчёты (источники, поведение) — через 24–48 часов.

## 6. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| В GA4 нет данных | Вставлен `GTM-...` или `UA-...` вместо `G-...`; либо не дано согласие на cookie |
| В Метрике нет данных | В поле попали `ym(...)`, кавычки или пробелы — нужны только цифры |
| Заявки не приходят в Telegram | Бот не добавлен в группу / не администратор; неверный `TG_CHAT_ID` (у групп он отрицательный); не заданы переменные на сервере |
| Бот в группе «молчит» | Не отключён privacy mode: @BotFather → `/setprivacy` → Disable |
| Ошибка «Сервер не настроен» при отправке формы | На сервере не заданы `TG_BOT_TOKEN` / `TG_CHAT_ID` |
| Заявка «отправлена», но не пришла | Сработала антиспам-защита (слишком быстрая отправка — форма должна заполняться дольше 3 секунд) |

## 7. Что в итоге отправить разработчику

```
1. Google Analytics 4 ID:  G-__________
2. Яндекс.Метрика ID:      __________
3. Telegram bot token:     ______________________  (секретно)
4. Telegram chat ID:       ______________________  (секретно)
5. Куда должны приходить заявки: личный чат / группа «...» / канал «...»
```

Пункты 1–2 можно внести самостоятельно в админке (`/keystatic` → «Настройки сайта» → «Аналитика»), пункты 3–4 передаются только разработчику для настройки сервера.

## Приложение. Технические примечания (для разработчика)

- Поля аналитики описаны в `keystatic.config.ts` и хранятся в `src/content/site/settings.yaml` (`analytics.ga4Id`, `analytics.yandexMetrikaId`).
- ID передаются на клиент через `data-ga4-id` / `data-yandex-metrika-id` в `src/layouts/BaseLayout.astro` и загружаются в `src/scripts/analytics.ts` только при наличии согласия `analytics`; при отзыве согласия трекеры и cookie удаляются.
- Метрика инициализируется с `clickmap`, `trackLinks`, `accurateTrackBounce`, `webvisor` — поэтому в счётчике нужно включить соответствующие опции, иначе часть данных не соберётся.
- Telegram-креды читаются через `getenv()` в `public/api/submit.php`; при отсутствии переменных API возвращает `500 «Сервер не настроен»`.
- Схема полей допускает пустые значения (`z.string().optional()`), поэтому пустые ID не ломают сборку — трекер просто не загружается.
