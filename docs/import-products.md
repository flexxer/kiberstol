# Импорт карточек товаров из xlsx

Скрипт переносит карточки из клиентских Excel-файлов в контентную коллекцию
`products` (Markdown + YAML frontmatter), чтобы не заводить товары руками в
Keystatic.

```bash
npm run import:products -- --dry-run     # показать план, ничего не писать
npm run import:products                  # создать отсутствующие карточки
npm run import:products -- --update       # + обновить юр. поля существующих
npm run import:products -- --force        # перезаписать всё
npm run import:products -- --source="путь/к/папке"   # другой источник
```

## Источник данных

По умолчанию — `downloads/client-files/Наполнение сайта/Карточки товаров/**`
(папка исключена из git, см. `.gitignore`). Ожидаемая структура:

```text
Карточки товаров/
  Meta/Карточки Meta.xlsx
  Teco/Карточки Teco.xlsx
  Tower/Карточки Tower.xlsx
  Допы/Карточки Допы.xlsx
```

Один лист = одна карточка. Линейка определяется по папке (Meta → `meta`,
Допы → `addons`), slug — по имени листа (`Tower 13WB` → `tower-13wb`).

## Что куда попадает

| Строка листа | Поле схемы `productsSchema` |
|---|---|
| `Наименование` | `title` (у подставок сверяется с именем листа — в xlsx бывает копипаст) |
| `Линейка` | `line`; у подставок ещё и `specs: Подходит для линеек` |
| `Материал` (2 колонки) | `specs`: материал столешницы / опор |
| `Цвет` | `specs`: цвет столешницы / опор (из скобок берётся название декора) |
| `Размер` | `specs`: ширина, глубина, высота (+ размер опор) |
| `Страна проиcхождения` | `countryOfOrigin` |
| `Гарантия` | `warranty` (`1 год` → `12 месяцев`) |
| `Изготовитель` (1–2 строки) | `manufacturer` + `manufacturerLocation` через `; ` |
| `Импортер` / `Поставщик` | `importer` / `supplier` |
| `Товар новый…` | `used: false` + блок `richText` |
| `Описание` | тело Markdown: вводный абзац жирным + список из `•`-пунктов |
| `Доп. комплектация` | блок-ссылка на подставку (`/products/<slug>`) |
| дисклеймер производителя | блок `richText` |

Не переносится: `«Показать полностью»` (подсказка интерфейса).

## Ручные правки и цены

`scripts/data/product-overrides.json` накладывается поверх импорта:

- `price` / `oldPrice` — **цены в xlsx отсутствуют**, сейчас это плейсхолдеры,
  актуальные значения вносятся через CMS;
- `badge`, `order`, `specs` (правки конкретных характеристик), `slug`;
- `defaults` — значения по умолчанию (`warranty`, `ctaText`).

Ключ объекта — slug карточки (`meta-wb`, `tower-13w`, `m13wb`).

## Режим `--update`

Меняет только юридические поля: `manufacturer`, `manufacturerLocation`,
`importer`, `supplier`, `countryOfOrigin`, `warranty`, `used`, `specs`.
Ручные значения (цена, бейдж, фото, галерея, порядок, SEO, краткое и полное
описание) сохраняются — поэтому им можно безопасно «освежать» карточки после
исправлений в xlsx.

## Ограничения

- **Фото.** Если нет `src/assets/uploads/<slug>/image.*`, подставляется фото
  линейки (`/assets/uploads/<line>/image.jpg`) — сборка и валидация проходят,
  но карточки временно выглядят одинаково. Оригиналы кладутся в
  `src/assets/uploads/<slug>/` (главное фото — `image.jpg`, галерея —
  `gallery/*`), после этого импорт подхватит их сам.
- **Импортёр.** Если в карточке не указан, для товаров с Китаем в составе
  подставляется поставщик, для товаров из РБ — «Импортёр отсутствует…».
  Значение стоит подтвердить у клиента.
- Повторный запуск без флагов ничего не перезаписывает (идемпотентно).
