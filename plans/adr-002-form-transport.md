# ADR-002 — Транспорт формы заявок и обращение с секретами

- **Статус:** Accepted
- **Дата:** 2026-10-23
- **Контекст:** рефакторинг формы заявок, [`plans/refactoring-form-v3.md`](refactoring-form-v3.md)

## Контекст

Сайт собирается статически (`output: 'static'`) и размещается на **hoster.by** (PHP-хостинг).
Node-адаптер `@astrojs/node` используется только для серверных маршрутов Keystatic
(`/keystatic`, `/api/keystatic`). Форма заявок должна отправлять данные в Telegram, но:

- Telegram-реквизиты появятся позже;
- `TG_BOT_TOKEN` и `TG_CHAT_ID` нельзя хранить в git;
- секреты не должны попадать в клиентский бандл, HTML, `data-*` или `dist/client`;
- форма должна тестироваться до получения боевых creds.

## Решение

1. **Статика сохраняется.** Контентные страницы остаются статическими.
2. **Приём формы — PHP-модуль** [`public/api/submit.php`](../public/api/submit.php:1),
   доступный по `/api/submit.php` на hoster.by.
3. **Секреты — только `getenv()` в PHP.** Переменные `TG_BOT_TOKEN` и `TG_CHAT_ID`
   задаются в окружении хостинга (панель, `SetEnv`, pool `env[...]`).
4. **Запрет клиентских префиксов.** Ни одна серверная переменная не получает префикс
   `PUBLIC_` и не читается через `import.meta.env` в клиентском коде.
5. **Dry-run.** `TG_DRY_RUN=1` выполняет валидацию, пишет запись в лог и возвращает
   `200 {ok:true, dryRun:true}` без обращения к Telegram. Это позволяет разрабатывать,
   тестировать и деплоить форму до появления creds.
6. **Health-check.** `GET /api/submit.php?health=1` возвращает
   `{ok:true, configured:bool, dryRun:bool}` без раскрытия значений секретов.
7. **Секрет-скан.** CI-скрипт `scripts/check-no-secrets.mjs` проверяет `dist/client`
   и `src` на `TG_BOT_TOKEN`, `TG_CHAT_ID`, `PUBLIC_TG_` и шаблон токена бота.
8. **Тесты — на реальном PHP.** Playwright поднимает `php -S -t dist/client` с
   `TG_DRY_RUN=1`; API-тесты проверяют коды 405/403/422/429/503/502 и health.

## Последствия

- Для работы формы hoster.by должен исполнять PHP. Это подтверждено.
- Node-процесс не участвует в приёме заявок; он нужен только для Keystatic.
- `dist/client/api/submit.php` — публичный файл, но не содержит секретов: только
  `getenv()`. Секрет-скан гарантирует отсутствие значений в сборке.
- При смене хостинга на Node-only контракт API сохраняется, а PHP заменяется на
  Astro API route отдельным ADR.

## Смежный риск: Keystatic на hoster.by

Форма от Node не зависит, но production-админка Keystatic — зависит: `@keystatic/astro`
инжектит серверные маршруты `/keystatic` и `/api/keystatic`, которым нужен Node-процесс.
На дешёвом тарифе hoster.by Node.js может быть недоступен или ограничен по ресурсам.

Варианты (решение — отдельным ADR, вне рамок формы):

| Вариант | Плюсы | Минусы |
|---|---|---|
| Node-процесс на hoster.by | один хостинг, простая схема | тариф, ресурсы, поддержка Node |
| Админка на отдельном Node-хостинге (Vercel/Render) + статика на hoster.by | не зависит от тарифа hoster.by | два деплоя, GitHub OAuth, синхронизация |
| Keystatic только локально, контент — через git/GitHub | минимум инфраструктуры | неудобно заказчику без разработчика |
| Другая CMS со статической админкой (Decap + OAuth proxy) | работает без Node | миграция контента и схем |

**Правило:** форма не должна блокироваться решением по Keystatic. Реализация формы
идёт параллельно; вопрос Keystatic фиксируется как отдельный трек с проверкой Node
на hoster.by.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Astro API route (`src/pages/api/submit.ts`) | Требует Node-процесса на хостинге; hoster.by подтверждён как PHP |
| Сторонний form-сервис | Секреты и ПД уходят третьей стороне; лишняя зависимость |
| `mailto:` / email-уведомления | Не соответствует ТЗ (заявки в Telegram) |
| Хранение creds в `.env` на сервере | `.env` не читается PHP-FPM автоматически; риск попадания в git |

## Правила безопасности

- `.env` и `.env.*` — в `.gitignore`; в репозитории только `.env.example` с пустыми значениями.
- Токен не логируется, не попадает в `error_log`, не выводится в ответах API.
- В Telegram уходит только текст заявки; IP и прочие метаданные не передаются.
- `LEADS_LOG_PATH` (если включён) — вне webroot, с ограниченными правами.
- При компрометации токена — `/revoke` в @BotFather и замена переменной на хостинге.
